## Query Pipeline Overview

The GraphRAG query pipeline answers questions over a knowledge graph generated by the [indexing pipeline](./graphrag-indexing-pipeline-reference.md). It supports **four search strategies**, each offering different trade-offs between speed, accuracy, and the type of question they handle best.

### Four Search Strategies

| Strategy | Approach | Best For | Data Required |
|---|---|---|---|
| **Local** | Graph-traversal: entity → relationships → communities → text | Specific, entity-focused questions | entities, relationships, community_reports, text_units, covariates |
| **Global** | Map-reduce over community reports | Broad, summarization-style questions | community_reports, communities, entities |
| **DRIFT** | Iterative retrieval with feedback loops | Exploratory, multi-step questions | community_reports, entities, relationships, text_units |
| **Basic** | Simple vector similarity search on text chunks | Quick baseline answers, simple facts | text_units |

### Common Query Flow

All four search strategies follow the same high-level pattern:

```
1. Load Data: Read parquet files from index output into typed data objects
2. Connect Vector Store: Open LanceDB/Azure AI Search for embeddings
3. Build Search Engine: Create strategy-specific search object with LLM model
4. Execute Search:
   a. Build Context: Retrieve + format relevant data from the graph
   b. Generate Prompt: Insert context into a system prompt template
   c. LLM Call: Send prompt + user query to the LLM
   d. Return Result: Structured SearchResult with response + context_data
```

## Global Search

**Files:**
- Search: `packages/graphrag/graphrag/query/structured_search/global_search/search.py`
- Context: `packages/graphrag/graphrag/query/structured_search/global_search/community_context.py`

### Overview

Global search uses a **map-reduce** approach over community reports:
1. **Map Phase**: Send each community report batch to the LLM, extracting key points with importance scores (0-100)
2. **Reduce Phase**: Collect all scored points, sort by score, synthesize final answer

### Search Algorithm

```python
class GlobalSearch(BaseSearch[GlobalContextBuilder]):
    async def search(self, query, ...) -> GlobalSearchResult:
        # Step 1: Build context batches from community reports
        context_result = await self.context_builder.build_context(
            query=query, **self.context_builder_params,
        )
        # context_chunks is list[str], one per community report batch

        # Step 2: MAP phase — process each batch concurrently
        map_responses = await asyncio.gather(*[
            self._map_async(query, context_chunk, ...)
            for context_chunk in context_result.context_chunks
        ])

        # Step 3: REDUCE phase — combine scored points
        response = await self._reduce_response(
            map_responses, query, max_length=self.reduce_max_length, ...
        )
        return GlobalSearchResult(response=response, map_responses=map_responses, ...)
```

### Map Phase

Each map call uses JSON mode to extract structured key points:
```python
# Prompt format: JSON {"points": [{"description": "...", "score": 0-100}, ...]}
# References data as [Data: Reports (report ids)]
```

### Reduce Phase

1. Collect all key points from map responses
2. Filter out points with score = 0
3. Sort descending by score
4. Fit into token budget (`data_max_tokens`, default: 12,000)
5. Format as `----Analyst N----` sections
6. Send to LLM for final synthesis

### Dynamic Community Selection

**File:** `packages/graphrag/graphrag/query/context_builder/dynamic_community_selection.py`

LLM rates each community's relevance instead of using a fixed level:

| Parameter | Default | Description |
|---|---|---|
| `dynamic_search_threshold` | 4 | Rating threshold (0-10) |
| `dynamic_search_keep_parent` | True | Keep parent if child relevant |
| `dynamic_search_num_repeats` | 1 | Rating passes per report |
| `dynamic_search_use_summary` | False | Rate summary vs full_content |
| `dynamic_search_max_level` | 2 | Max hierarchy level |

### Key Parameters

| Parameter | Default | Description |
|---|---|---|
| `max_context_tokens` | 8,000 | Context per map batch |
| `data_max_tokens` | 12,000 | Max tokens in reduce input |
| `map_max_length` | 1,000 | Map output words |
| `reduce_max_length` | 2,000 | Reduce output words |

## DRIFT Search

**Files:**
- Search: `packages/graphrag/graphrag/query/structured_search/drift_search/search.py`
- Context: `packages/graphrag/graphrag/query/structured_search/drift_search/drift_context.py`
- Primer: `packages/graphrag/graphrag/query/structured_search/drift_search/primer.py`
- Action: `packages/graphrag/graphrag/query/structured_search/drift_search/action.py`
- State: `packages/graphrag/graphrag/query/structured_search/drift_search/state.py`

### Overview

DRIFT (Dynamic Retrieval with Iterative Feedback and Traversal) is the most sophisticated strategy:

1. **Global primer**: Find relevant community reports via embedding similarity
2. **Local search**: Deep exploration of each finding
3. **Iterative refinement**: Repeat for N depth levels, updating query state
4. **Reduce**: Synthesize all findings into a final answer

### Search Algorithm

```python
class DRIFTSearch(BaseSearch[DRIFTSearchContextBuilder]):
    async def search(self, query, ...) -> SearchResult:
        # Step 1: Primer — find top-k community reports via cosine similarity
        top_k_results, token_ct = await self.context_builder.build_context(query)

        # Step 2: Process primer results into folds
        primer_output = await self.primer(query, top_k_results)

        # Step 3: Iterative search (n_depth levels, default: 3)
        for level in range(self.context_builder.config.n_depth):
            for node in self.query_state.get_focus_nodes():
                local_result = await self.local_search.search(
                    query, drift_query=primer_output, ...
                )
                actions = await DriftAction(self.model, ...)(local_result, query)
                self.query_state.update(actions, level)

        # Step 4: Reduce — synthesize all findings
        response = await self._reduce_response(self.query_state.get_state(), query)
        return SearchResult(response=response, ...)
```

### Primer Phase

`DRIFTSearchContextBuilder.build_context()`:
1. Embeds user query via `PrimerQueryProcessor`
2. Computes vectorized cosine similarity against all community report `full_content_embedding` vectors
3. Returns top-k reports (`drift_k_followups`, default: 20)

### Primer Query Processor

Splits top-k reports into folds (`primer_folds`, default: 5), asks LLM to extract key insights per fold, then combines them. This primes the local search for follow-ups.

### Key Parameters

| Parameter | Default | Description |
|---|---|---|
| `drift_k_followups` | 20 | Top global results |
| `primer_folds` | 5 | Primer split folds |
| `n_depth` | 3 | Iterative search levels |
| `concurrency` | 32 | Concurrent LLM requests |
| `data_max_tokens` | 12,000 | Max data tokens |
| `local_search_text_unit_prop` | 0.9 | Text unit proportion |
| `local_search_community_prop` | 0.1 | Community proportion |
| `local_search_top_k_mapped_entities` | 10 | Entities per local search |
| `local_search_top_k_relationships` | 10 | Relationships per local search |

## Basic Search

**Files:**
- Search: `packages/graphrag/graphrag/query/structured_search/basic_search/search.py`
- Context: `packages/graphrag/graphrag/query/structured_search/basic_search/basic_context.py`

### Overview

Simple RAG — embed query, find top-k similar text units via vector search, generate answer.

### Search Algorithm

```python
class BasicSearch(BaseSearch[BasicContextBuilder]):
    async def search(self, query, ...) -> SearchResult:
        # Step 1: Build context
        context_result = self.context_builder.build_context(
            query=query, **self.context_builder_params,
        )
        # Step 2: Format prompt
        search_prompt = self.system_prompt.format(
            context_data=context_result.context_chunks,
            response_type=self.response_type,
        )
        # Step 3: LLM completion
        response = await self.model.completion_async(
            messages=[system_msg, user_msg], stream=True, **self.model_params,
        )
        return SearchResult(response=full_response, ...)
```

### Context Building

`BasicSearchContext.build_context()`:
1. Embeds query via `text_embedder.embedding()`
2. Calls `text_unit_embeddings.similarity_search_by_text(text=query, k=10)`
3. Filters text units to matched IDs
4. Fills context window up to `max_context_tokens` (default: 12,000)
5. Returns context as CSV-formatted text

### Parameters

| Parameter | Default | Description |
|---|---|---|
| `k` | 10 | Text units to retrieve |
| `max_context_tokens` | 12,000 | Max context window |

## Search Comparison Matrix

| Aspect | Local | Global | DRIFT | Basic |
|---|---|---|---|---|
| **Graph Traversal** | ✅ Entity → relations | ❌ No | ✅ Entity → relations | ❌ No |
| **Community Reports** | ✅ Used as context | ✅ Core data | ✅ Used for primer | ❌ No |
| **Entity Search** | ✅ Semantic vector | ❌ No | ✅ Semantic vector | ❌ No |
| **Text Unit Search** | ✅ Graph-linked | ❌ No | ✅ Graph-linked | ✅ Direct vector |
| **LLM Calls** | 1 (single) | N+1 (map+reduce) | Many (iterative) | 1 (single) |
| **Context Window** | Single call | Multiple parallel | Multiple iterative | Single call |
| **Complexity** | Medium | Medium | High | Low |
| **Best For** | Specific questions | Broad overviews | Exploratory | Quick facts |
| **Conversation History** | ✅ Yes | ✅ Yes | ❌ No | ✅ Yes |

### DRIFT Search Detail Flow

```
1. PRIMER: Find top-k community reports via cosine similarity
   │
   ▼
2. PRIMER PROCESSING: Split into folds, LLM extracts insights
   │
   ▼
3. ITERATIVE SEARCH (n_depth times, default: 3):
   For each focus node:
     a. LocalSearch with drift context
     b. DriftAction: generate follow-up entities/queries
     c. Update QueryState
   │
   ▼
4. REDUCE: Synthesize all responses into final answer
```

## Copilot Agent Integration Notes

### Quick-Start: Local Search

```python
import asyncio
from pathlib import Path
from graphrag.config.load_config import load_config
from graphrag_storage import create_storage
from graphrag_storage.tables.table_provider_factory import create_table_provider
from graphrag.data_model.data_reader import DataReader
from graphrag.query.indexer_adapters import (
    read_indexer_entities, read_indexer_reports,
    read_indexer_text_units, read_indexer_relationships,
)
from graphrag.query.factory import get_local_search_engine
from graphrag.utils.api import get_embedding_store

async def query_local(root_dir: str, query: str, community_level: int = 2):
    config = load_config(root_dir=Path(root_dir))

    # 1. Load data
    storage = create_storage(config.output_storage)
    table_provider = create_table_provider(config.table_provider, storage)
    reader = DataReader(table_provider)

    entities_df = await reader.entities()
    communities_df = await reader.communities()
    reports_df = await reader.community_reports()
    text_units_df = await reader.text_units()
    relationships_df = await reader.relationships()

    # 2. Convert to typed objects
    entities = read_indexer_entities(entities_df, communities_df, reports_df, community_level)
    reports = read_indexer_reports(reports_df, communities_df, community_level)
    text_units = read_indexer_text_units(text_units_df)
    relationships = read_indexer_relationships(relationships_df)

    # 3. Connect vector store
    description_embedding_store = get_embedding_store(config.vector_store, "entity_description")

    # 4. Create search engine
    search_engine = get_local_search_engine(
        config=config, reports=reports, text_units=text_units,
        entities=entities, relationships=relationships, covariates={},
        response_type="Multiple Paragraphs",
        description_embedding_store=description_embedding_store,
    )

    # 5. Execute
    result = await search_engine.search(query)
    print(f"Response: {result.response}")
    print(f"LLM Calls: {result.llm_calls}, Tokens: {result.prompt_tokens}+{result.output_tokens}")
    return result
```

### All Four Strategies

```python
from graphrag.api import local_search, global_search, drift_search, basic_search

async def search_all(config, query: str, community_level: int = 2):
    # Load data
    storage = create_storage(config.output_storage)
    table_provider = create_table_provider(config.table_provider, storage)
    reader = DataReader(table_provider)

    entities_df = await reader.entities()
    communities_df = await reader.communities()
    reports_df = await reader.community_reports()
    text_units_df = await reader.text_units()
    relationships_df = await reader.relationships()

    # Local Search
    resp, ctx = await local_search(config, entities_df, communities_df, reports_df,
                                     community_level, False, "Multiple Paragraphs", query)
    print(f"Local: {resp[:200]}...")

    # Global Search
    resp, ctx = await global_search(config, entities_df, communities_df, reports_df,
                                      community_level, False, "Multiple Paragraphs", query)
    print(f"Global: {resp[:200]}...")

    # DRIFT Search
    resp, ctx = await drift_search(config, entities_df, communities_df, reports_df,
                                     text_units_df, relationships_df, community_level,
                                     "Multiple Paragraphs", query)
    print(f"DRIFT: {resp[:200]}...")

    # Basic Search
    resp, ctx = await basic_search(config, text_units_df, "Multiple Paragraphs", query)
    print(f"Basic: {resp[:200]}...")
```
